# IPScanner 产品建议书（v1.7.6 基线）

> 实测数据与同类产品（Advanced IP Scanner / SoftPerfect / Fing / Lansweeper /
> Total Network Inventory / Auvik / Domotz / Netdisco / LibreNMS / Nmap 等）的功能对标。

## 0. 结论摘要

**一句话**：这是一个**工程质量远超同类个人项目**、但**产品形态还没定型**的桌面工具。
它现在最像「Advanced IP Scanner 的加强版 + 一点 Lansweeper + 一点 UVexplorer」，
三块都做到了 60 分，但没有一块是「为了它才装这个软件」。

十二条最重要的建议，按重要性排序：

| # | 建议 | 为什么 | 量级 |
|---|---|---|---|
| 1 | **把「不限设备、不限站点、无需账号、无需上云」当成第一卖点写进 README 首屏** | 同类产品的免费档全是「限 3 台 / 限 10 台 / 每天 3 次扫描」`[对标]`，而本项目**没有**任何这类限制 —— 这是现成的、零成本的差异化 | 文案级 |
| 2 | **加「被动/持续发现」模式** | 现在产品形态是「我跑一次扫描」，而这类工具真正的价值是「一份可信的台账」。做法：定时轮询本机 **ARP/NDP 缓存**（不发包、不惊动 IDS）+ `zeroconf` mDNS/DNS-SD 常驻 + 周期性 SSDP `M-SEARCH`。这是把产品从「扫描器」推进到「台账」的那一步 `[对标]` | 1 周 |
| 3 | **加「这台设备插在哪」定位：MAC/IP → 交换机端口（含历史）** | **数据已经在你手里了** —— `switch_mapper` 每次都在走 `dot1dTpFdbTable`。做成跨交换机的 FDB 索引后，「10.0.0.57 挂在 access-sw-2 的 GE1/0/7」是一句话的事。Netdisco 靠这个功能立身，而它是**局域网里被问得最多的问题**`[对标]` | 3–5 天 |
| 4 | **数据模型从「快照」升级为「资产 + 观测」两层** | 现在每个问题都要把**全部历史行**捞进内存聚合：`query_history` 实测 4 万行 605ms，且跑在 GUI 线程上；/16 × 20 快照 = 130 万行会直接冻结界面。资产表之后，#2/#3 的「历史位置」「在线率曲线」才真正便宜 | 1–2 周 |
| 5 | **加只读 HTTP API（`ipscanner serve`）+ 结构化 webhook 事件** | 领域层**已经全部零 Qt 依赖**（scanner / topology / history / risk / change / notifier / scheduler 全都不 import PyQt5），做 API 基本只是接线；没有 API 就没有集成、没有看板、没有 CI 用法 | 1 周 |
| 6 | **维护窗口 / 告警抑制 / 通知去重** | 这是同类产品**用户抱怨最多**的一条（Auvik 被吐槽「打印机缺纸都发工单」、无 mute 窗口）`[对标]`；本项目已有 scheduler + 四类通知，缺这一层就还是会变成噪声源 | 2–3 天 |
| 7 | **加「零利用」的安全体检**：TLS 证书到期、SMB 方言与签名、弱协议、**LAN 里存在 LLMNR/NBNS 响应器** | 全部只用标准库、全部不涉及任何漏洞利用 —— **风险为零、信号极强**。尤其：Windows 11 24H2 / Server 2025 起 **SMB 签名默认必需**，所以"签名未启用"就是一个真实偏差；CISA CM0053（2025-03）已建议**关闭 LLMNR**，所以网里还有响应器本身就是一条发现 `[对标]` | 3–5 天 |
| 8 | **迁移 PyQt5 → PySide6** | 一箭四雕：① GPL-3.0 → LGPL-3.0，解开「不能被企业集成/闭源分发」的锁；② Windows 上不再捆 2021 年的 Qt 5.15.2（PyQt5-Qt5 在 Windows 只有 5.15.2，上游开源支持早已结束，Linux 尚有 KDE 补丁集、Windows 没有）；③ 跟上仍在维护的 Qt 6；④ **PyQt5 没有官方 Windows ARM64 wheel，而 PySide6 有** —— 不迁移就永远上不了 ARM64 | 3–5 天 |
| 9 | **拓扑视图在 10 台以上交换机时不可读（可复现），顺带补文本版导出** | `[实测]` 10 交换机/1000 终端 → 画布 7326×990；50 交换机/5000 终端 → 36926×990。`fitInView` 缩到 3% 后什么都看不见。需要「过宽就换行/分栏」；同时补树/Markdown/ASCII 文本版（同类都不做，Auvik 用户却说文本版比图更有用） | 2–3 天 |
| 10 | **历史查询/对比挪到后台线程 + 加分页与过滤下推** | `[实测]` 查询无 LIMIT、无分页、无进度、无取消，且同步跑在 GUI 线程 | 1–2 天 |
| 11 | **代码签名走 SignPath Foundation（开源免费），并从第一个签名版本开始连续签** | 现在是「未签名 + SmartScreen 拦截」，README 只能教用户点「仍要运行」。`[对标]` 2024 起 **EV 证书不再免 SmartScreen**（别买）；Azure Artifact Signing 个人开发者**仅限美加**。**关键**：新版 SmartScreen 信誉按"同一签名身份持续发布"累积，所以越早开始签越值钱 | 1–3 天（申请为主） |
| 12 | **补三道质量门禁：覆盖率（仅领域层）/ pyright（仅领域层）/ `pip-audit`；把手写 BER 的 fuzz 固化成测试** | 领域层零 Qt 是天然的类型检查边界；1116 个测试没有覆盖率数字就不知道测到了哪。BER fuzz 本次实测已通过（6 万随机 + 4 万变异，零异常），固化只需几十行 | 2–3 天 |

## 1. 现状体检

### 1.1 工程面：这是项目最大的资产

`[实测]` 代码量（非空行）：

| 区域 | 文件数 | 行数 |
|---|---|---|
| 根目录（UI / 业务 / 入口） | 48 | 12 772 |
| `scanner/`（引擎层） | 19 | 5 057 |
| `ui_dialogs/`（对话框包） | 9 | 1 796 |
| `tests/` | 58 | 11 772 |

测试 : 产品代码 ≈ **0.6 : 1**，共 **1116 个用例**。同类个人项目通常在 0.05–0.1。
以下几条是「比大多数商业小工具还严」的地方，值得保持：

- **单一版本源** + 测试强制 `pyproject.toml` 与 `version.py` 一致；
- **i18n 完整性用 AST 校验**，新增中文文案忘了加英文会**测试失败**；
- **静默吞异常棘轮**（只准降不准升）+ 每个静默 `except` 必须写理由；
- **色值字面量禁令**（`ui_dialogs` 内零字面量，且令牌名必须在 `theme_tokens` 里存在）；
- **三平台 CI × 四解释器矩阵 + 打包产物完整性断言**（断言到 `_internal/oui.db`、`assets/styles/light.qss` 这一级）；
- **无第三方依赖的核心**：手写 BER 编解码（SNMP v2c/v3）、ctypes 原生 ICMP/ARP、纯标准库 AES。

> **实测补充**：手写的 SNMP BER 解析器（`scanner/snmp.py`）在 **6 万次随机字节** + **4 万次
> 从合法响应变异的 fuzz** 下**零未捕获异常**。这块代码的健壮性比预期好 —— 建议把这套
> fuzz 固化成测试（见 §5.3），而不是「去修一个不存在的 bug」。

### 1.2 产品面：功能横跨四个品类，但没有一个是「必装理由」

现有能力大致可归到四类，每类的成熟度不同：

| 品类 | 本项目现状 | 与品类标杆的差距 |
|---|---|---|
| **局域网扫描器** | 很强：原生 ICMP（比子进程 ping 快约 370×）、ARP 补禁 Ping 主机、三档端口深度、connect/SYN/UDP、RTT 自适应超时 | 缺 **IPv6**、缺 **TLS 证书到期**、缺**远程动作包**（WoL/关机的覆盖面）、Windows 上 SYN 需 Npcap |
| **资产台账** | 中：SQLite 快照（保留 20 份）、Excel 台账匹配、变更检测（MAC 为身份）、首见/末见、时间线 | 缺**当前态资产表**、缺**软件/许可清单**、缺**保修/EOL 字段**、缺**自定义字段** |
| **网络监控/告警** | 中偏弱：schtasks/crontab 定时扫描 + Webhook/企微/钉钉/邮件 | 缺**维护窗口**、缺告警去重/聚合、缺**持续状态**（只有「每次扫描」这一个事件源） |
| **拓扑/网络图** | 中：四档退化（LLDP/CDP → BRIDGE-MIB 转发表 → 无链路说明 → /24 分层），诚实不画假链路 | 缺**手工校正**、缺**导出图片/Visio**、缺**端口利用率**、**宽网络不可读** |

### 1.3 三个结构性约束（不是 bug，是设计选择带来的天花板）

**(a) 快照模型 ⇒ 每个问题都是 O(全部历史行)**
`[实测]` 2 000 设备 × 20 快照（4 万行 / 5.8 MB）：写入 0.90s；`query_history` **605ms**；
`load_all` **310ms**；`device_timeline`（有索引）0.5ms。
按同比例，**`/16` × 20 快照 = 130 万行**：查询会到秒级甚至十几秒 —— 而它
`ui_dialogs/history.py::_run_query()` 是**同步跑在 GUI 线程**上的（无 QThread、无进度、无取消、SQL 里**没有 LIMIT**）。

**(b) 只有 IPv4，且是「输入即拒绝」**
这是个**诚实**的选择（好过扫出一张假的全离线表），但 2026 年双栈网络已经普遍。
`[对标]` SoftPerfect（同价位桌面标杆）已支持 IPv6，且 IPv6 缺失被列为该品类的十大抱怨之一。

**(c) 许可证被 PyQt5 锁死在 GPL-3.0**
这不是「选错了」，是 PyQt5 的客观约束（GPL-3.0 / 商业双授权）。但它决定了：
- 不能被闭源产品集成、不能做「开源核心 + 闭源增值模块」（除非买 Riverbank 商业授权或迁 PySide6）；
- 企业法务对 GPL 的接受度明显低于 LGPL —— 这一条**直接影响装机量天花板**。

## 2. 定位：先决定「不做成什么」

三条可选的路线，我建议**明确选 A，把 C 当第二增长点，B 只维持不扩张**：

**A. 桌面端的「内网体检 + 资产台账」专家（建议主路线）**
- 目标用户：中小企业 IT / 网管 / 集成商售前，一个人在 Windows 上干活。
- 差异点：**中文优先 + 零依赖 + 无账号无云 + 不限设备 + CLI 可脚本化 + 诚实降级**。
- 与它的竞争关系：Advanced IP Scanner（免费但无 SNMP/无历史/无拓扑）、
  SoftPerfect（功能最全但付费、且是「工具集」而非「台账」）、
  Total Network Inventory（最像的付费对手，约 $90/25 节点 `[对标]`）。
- 关键动作：把「扫描 → 台账 → 变更 → 报表」这条闭环做**顺**，而不是继续加发现协议。
- **一句话的形态转变**：从「**我跑一次扫描**」变成「**我有一份会自己更新的台账**」。
  现在整个产品是"事件驱动"的（按一次「扫描」按钮 → 得到一张表）；
  这条路线要求它变成"状态驱动"的（后台安静地持续知道网里有什么、什么变了）。
  §0 的 #2（被动发现）+ #4（资产表）合起来就是这个转变，**这也是本建议书里最重要的一条产品判断**。

**B. 无代理轻量网络发现 + 拓扑（对标 Netdisco / UVexplorer 的桌面版）**
- 天花板明确：拓扑做深需要持续采集 + 配置备份 + 手工校正，是**另一个产品**。
- 建议：只做「拓扑图 + 文本版导出 + 手工校正」，不做配置备份/自动化编排。

**C. CLI/CI 友好的暴露面与合规巡检（建议作为第二增长点）**
- 本项目已有：CLI（scan/diff/history/schedule）、风险评分（0–100 且**每分可解释**）、
  快照、JSON 输出。这套组合在「每月跑一次、出个报告、对比上月」场景里已经**接近可用**，
  只差**报告**和**退出码语义**。
- 这条线的好处：**不需要 GUI**，因此不受许可证约束的困扰，也最容易进 CI。

**明确不做**（理由见 §9）：SNMP 轮询式监控（Zabbix/PRTG 的地盘）、
配置备份与合规基线（Oxidized/NetCrunch 的地盘）、流程编排（NetBrain 的地盘）、
云端 MSP 多租户平台。

## 3. 同类产品对标

> 详细资料见 `docs/research/`（本次新增的三份调研原始文件）。本节只留结论。

### 3.1 四个梯队与它们各自「卖的是什么」

| 梯队 | 代表 | 用户为什么装/买 | 对本项目的含义 |
|---|---|---|---|
| 免费桌面 | Advanced IP Scanner（自称 7000 万用户）、Advanced Port Scanner、NirSoft | 秒开、便携、够用；**用免费工具卖别的东西**（Famatech 卖 Radmin） | 本项目在功能上已全面超过 AIPS（有 SNMP/历史/拓扑/风险/CLI），**但没人知道** |
| 付费桌面 | SoftPerfect Network Scanner、Total Network Inventory、NetCrunch、UVexplorer | SoftPerfect = 工具最全；TNI = **变更日志 + 网络图 + 软件许可**；UVexplorer = **端口级 L2 拓扑 + 导出 Visio/PDF/SVG** | 这是最直接的竞争面。**TNI 约 $90/25 节点**决定了桌面 SKU 的价格天花板很低 |
| 小 MSP / RMM | Domotz（€35/站点/月、**设备不限**）、Auvik（按设备分三类计价） | **持续监控 + 远程动作 + 集成（PSA/IT Glue/Hudu）** | 本项目**不应**进入，但可吸收它们的「单站点不限设备」定价哲学 |
| 开源 / 自建 | NetAlertX、Netdisco、LibreNMS、Observium、Zabbix、NetBox、Oxidized、Nmap | 自建、可编程、深度 SNMP、作为**事实来源（SoT）** | 大多**不是**竞争者而是集成对象（见 §4.7）。**但要盯住 NetAlertX** |

两条必须知道的事实 `[对标]`：

- **NetAlertX 是最接近本项目的开源对照物**：Python + 本地 SQLite + GPL-3.0，
  **7 259 star 且只有 25 个未关闭 issue**。它的定位是「已连接设备的事实来源 + 影子 IT 告警」。
  它的 Plugins API / Workflows（声明式事后规则）/ Sync Nodes / Prometheus 导出 /
  基于 Apprise 的 80+ 通知服务，都是本项目可以直接借鉴的**低成本高杠杆**设计。
  值得注意的是：它的**数据来源不只是自己扫**，还包括 Pi-hole 数据库、DHCP 租约、UniFi 控制器、
  SNMP 路由器导入 —— **"借别人的租约"** 这个思路值得抄（本项目的 mDNS/ARP 缓存读取就是同一类手法）。
- **The Dude（MikroTik）已正式停止开发**（官方原文：discontinued、legacy、no further updates）。
  它原本占着「免费 + 自动发现 + 实时网络图」这个生态位 —— **这个位置现在空着**，
  而这恰好是本项目拓扑能力的形状。
- 另一条结构性优势：**NetBox 完全没有发现能力**（官方立场就是"NetBox 不是发现工具"）。
  所以「发现」这件事在开源生态里是有分工的 —— 本项目的正确姿势是**产出可导入的标准格式**，
  而不是去抢"事实来源"的位置。

### 3.2 该品类用户的抱怨排行榜（→ 直接就是机会清单）

`[对标]` 按出现频次排序（来自 Auvik/Lansweeper/PRTG/Fing 的评测与论坛）：

1. **按设备/传感器计价导致成本随规模爆炸**（Auvik 把工作站算「edge」、PRTG 按传感器、Lansweeper 超量 20–40% 罚金）
2. **告警噪声 + 没有维护窗口/静音**（Auvik：打印机缺纸也开工单；无 1–4 点备份白名单）
3. **拓扑图画错且**不能手工修正（父子关系错、僵尸节点删不掉、工作站被画成 AP、链路无速率）
4. **设备识别失败**：拿不到主机名、DHCP 换了地址就认不出是同一台（Domotz 正是拿 **MAC 身份**打这一点做卖点）
5. **规模一上来 UI 就卡**（830 个节点的图「不流畅」）
6. 不透明的报价 / 续费涨价 / 只给销售报价
7. 强制云账号 + 隐私顾虑（Fing 必须注册账号）
8. 免费档太小气（SoftPerfect 试用只显示 10 台、OpManager 免费 3 台、Fing 每天 3 次）
9. 学习曲线陡，一线技术员进不去
10. **低档位没有 API/集成**（要自动化就得买更高档）

> **本项目已经天然满足 1、6、7、8、10**，并且在 4 上已有正确的地基（变更检测以 MAC 为身份）。
> 剩下要补的**只有 2、3、5、9** —— 这四条就是 v1.8 的最佳靶心。

### 3.3 三条可以直接抄的「包装」思路

1. **「免费核心不设限」是最便宜的护城河** `[对标]` —— 直接写进 README 首屏与 Release 说明。
2. **计量单位选「站点」而不是「设备」**（Domotz/Fing Professional）—— 万一将来要做增值，
   按站点比按设备被骂得少得多。
3. **代价敏感型增值**（TNI 证明了这个价位存在）：把「多人共享的资产库服务器 / 加密凭据库 +
   审计 / 定时扫描服务 / 品牌化 PDF 报表 / 配置备份」做成增值包，而不是把核心功能砍掉做试用水印。

## 4. 功能建议（按模块）

### 4.1 发现与扫描

| 建议 | 理由与做法 | 优先级 |
|---|---|---|
| **异步 connect 扫描** | Windows 上 SYN 扫描要 Npcap，绝大多数用户装不上（**且 Npcap 免费授权只有 5 次安装、明确禁止再分发，不能随包捆绑** —— 见 §9），于是永远退化成 connect。而 `asyncio` + ProactorEventLoop(IOCP) 能在**不需要任何驱动**的前提下开几千个并发 connect，把 connect 扫描的速度拉到接近 SYN 的水平。这是「不加依赖就提升体感」的最大单点 | P1 |
| **被动/持续发现模式** | `[对标]` 定时轮询本机 **ARP / NDP 缓存**（不发包、不惊动 IDS）+ `zeroconf` 常驻 mDNS/DNS-SD + 周期性 SSDP `M-SEARCH`。这是把产品从「扫描器」变成「台账」的关键一步，也是最接近本项目的开源对照物 NetAlertX 的核心能力 | **P1** |
| **IPv6（只做"可见性"，不做全量资产）** | 阶段 1：允许输入 IPv6，做 **NDP 邻居发现（读 NDP 缓存 + 主动 NS）** + **ICMPv6 到 `ff02::1`**（链路本地多播回显，**常可在非管理员下工作**，与 IPv4 原始 ICMP 必须提权形成对比）+ **mDNS over v6**。不做 IPv6 端口扫描与完整资产盘点（见 §9）。关键坑：链路本地地址必须带 `%scope_id`，多播要按接口发 | P1（可见性） |
| **无线层（只切一小片）** | `[对标]` Windows 上用 **Native Wi-Fi API**（`wlanapi`）能拿到：信道拥塞、关联/漫游日志、SSID↔BSSID↔子网 的对应关系。这三点对「为什么这个会议室网速慢」「这台设备连的是哪个 AP」已经够用。**monitor 模式在 Windows 上是死路**，不要投入 | P2 |
| **扫描节流与礼貌模式** | 企业网里全速 SYN 会被 IDS 判定为扫描攻击。给一个「并发上限 + 随机化顺序 + 每分钟包数上限」的礼貌档，并在导出/审计里记录该档位 | P2 |
| **扫描目标文件** | 支持从文件读目标（`-iL targets.txt`，nmap 习惯），便于脚本化 | P3 |
| **端口→服务的映射外置** | `service_fingerprints.json` 已可外置；把 `COMMON_PORTS` / `_PORT_NAME_TEXT` 也做成同类可外置数据，用户能按行业调整（工控、医疗设备） | P3 |

### 4.2 识别与指纹

| 建议 | 理由与做法 | 优先级 |
|---|---|---|
| **TLS 证书采集** | 一条 `ssl` 握手（标准库）就能拿到 CN/SAN/签发者/**到期日**。到期日是这个品类里回报最高的字段之一（SoftPerfect 有），而且能直接接进风险评分（「证书 30 天内到期」） | P1 |
| **零利用的安全体检**（见 §4.5） | TLS 到期 / SMB 方言与签名 / 弱协议 / LLMNR·NBNS 响应器存在 —— 全部只用标准库、不做任何利用尝试。**这是风险最低、信号最强的一组新字段** | P1 |
| **设备身份：MAC 为主，但必须显式处理"随机化 MAC"** | 变更检测已按 MAC 做（正确）。但 `[对标]` 现代手机/Windows 会**随机化 MAC**，IPv6 还会用隐私地址 —— 纯 MAC 身份在这些设备上会「每次都当成新设备」。做法：用首字节的**本地管理位（bit 1）**识别随机 MAC，对这类设备退化到「主机名 + DHCP/协议指纹」身份，并在界面上明确标注「随机化 MAC，身份不可靠」。**不要**假装 MAC 永远稳定 | P1 |
| **名称解析来源要跟着时代换** | `[对标]` CISA CM0053（2025-03）建议**关闭 LLMNR**（MitM/凭据窃取），微软确认 **WINS 将在 Server 2025 之后移除**。含义有二：① **mDNS 应升级为名称的主来源**；② 网里**还存在 LLMNR/NBNS 响应器本身就是一条安全发现**（见 §4.5），而不只是"一个名称来源" | P1 |
| **SSH 主机密钥 / 指纹** | 对 `22` 开放的主机取一次 host key 指纹，可作**设备指纹**（重装系统会变），也是安全审计项 | P2 |
| **IoT / OT：只做只读识别** | `[对标]` 只加**被动/只读识别**：BACnet `Who-Is`、Modbus FC43/MEI 14 设备标识、**Matter 通过 mDNS 的 `_matter`/`_matterc`/`_meshcop` TXT 记录**（Nmap 2026-05 的 `matter-identify` 脚本已证明可行）。**绝不实现任何写操作或协议栈** | P2 |
| **SMB 方言 / 签名 / 来宾访问** | 对 445 开放主机探测 SMB 方言与签名要求。`[对标]` **Windows 11 24H2 / Server 2025 起 SMB 签名对入向/出向连接默认必需** —— 所以"签名未启用"从一个普通字段变成了**真实偏差**；SMB1 存在 = 高风险；允许来宾 = 高风险 | P2 |
| **指纹库版本化 + 反模式报告** | 数据文件已有外置机制，再加「指纹库版本」显示与「某指纹误判」的一键反馈（本地生成报告，用户自行决定是否发出） | P3 |

### 4.3 资产与历史（**最需要动结构的一块**）

**核心建议：引入「资产表 + 观测表」两层模型。**

```
assets(id, identity_key[MAC], first_seen, last_seen, seen_count,
       ip_current, hostname_current, vendor, device_class, os_guess,
       location, user, remark, custom_json, ...)
asset_observations(asset_id, snapshot_id, ip, status, open_ports, risk_score, ...)
snapshots(id, time, note)          -- 保留现有语义
```

收益（都是现在做不到或很贵的）：
- `query_history` 从「捞 130 万行再聚合」变成「查一张 6.5 万行的资产表」；
- 「当前台账」变成一个**独立概念**（而不是「最后一份快照」），这是资产管理的正统做法；
- 趋势类功能变得可能：在线率曲线、首次出现告警、**端口长期暴露时长**、MTBF/抖动；
- 报表、REST API、NetBox 同步都只需要读 `assets`。

配套的小改动（可以独立做，不需要等大改）：
- `query_history` 加 `limit` / `offset`，并把 `device_class` / 网段过滤**下推到 SQL**；
- 两个历史对话框的查询搬到 `QThread`（本项目已有成熟模式：`ui_threads.py` + `bounded_pool`）；
- 给 `devices` 表加 `PRAGMA user_version` 与迁移链（现在是 `CREATE TABLE IF NOT EXISTS`，
  加列就只能靠 `ALTER TABLE` 手写，没有版本号就无法安全演进）。

| 建议 | 优先级 |
|---|---|
| 资产表 + 观测表（含迁移脚本与兼容读旧库） | **P0（v2 主题）** |
| `user_version` + 迁移链 | P1 |
| 查询下推 + 分页 + 后台线程 | P1 |
| 自定义字段（`custom_json` + 列预设里可选显示） | P2 |
| 资产生命周期字段（采购日期/保修/负责人/序列号/位置树）+ EOL 提醒 | P2 |
| 软件清单与许可合规（需 WMI/注册表深度采集，Windows 专属） | P3 |

### 4.4 拓扑

| 建议 | 理由与做法 | 优先级 |
|---|---|---|
| **修「宽网络不可读」** | `[实测]` 10 交换机 → 7326×990，50 交换机 → 36926×990。做法：tidy tree 算出坐标后，若 **宽高比 > 3**，把并列子树**折成多行**（按行装箱），或把每一层按固定列数换行；等价于把「一排交换机」变成「一片」。已在 §6 给出验收标准 | **P1** |
| **手工校正 + 节点固定** | 同类产品**抱怨最集中的拓扑问题**。最小可用版：允许「把某节点钉在某坐标」「隐藏某条链路/某节点」「给节点加备注」。做成 `topology_overrides.json`，与扫描结果解耦 | P1 |
| **文本版拓扑导出** | 树形缩进 / Markdown 表格 / ASCII 三种，含端口与协议。**同类产品都不做**，而它是可访问性与工单粘贴的双赢 | P1 |
| **导出图片（PNG/SVG）与 draw.io/Visio** | `QGraphicsScene.render` 出 PNG 是现成能力（本次评审就用它做的验证图）；SVG 用 `QSvgGenerator`。draw.io 可导出 `.drawio` XML（简单） | P2 |
| **端口利用率与「空闲口」视图** | 转发表已经拿到了每个口的 MAC 列表 → 可以直接给「这个口接了几台设备」「哪些口是空的」。运维价值很高，且不需要新协议 | P2 |
| **「这台设备插在哪」定位（MAC/IP → 交换机端口）** | 见 §0 第 2 条。跨交换机 FDB 索引 + 历史（从快照里查上周的位置）。**这是 Netdisco 的招牌能力，而本项目的原始数据已经齐了** —— 缺的只是一个跨交换机的内存/DB 索引和一个搜索框 | **P1** |
| **链路速率/双工（LLDP 扩展 MIB / ifSpeed）** | 图上有速率才像「真拓扑」（Auvik 被吐槽链路无速率） | P3 |
| **VLAN / 子网着色** | 按 VLAN 或 /24 给节点与链路着色，跨网段场景立刻可读 | P3 |

### 4.5 安全与合规

现状很好的一点：**首次启动授权声明 + 审计日志 + 风险评分可解释**。可继续做深：

| 建议 | 理由 | 优先级 |
|---|---|---|
| **补一组「零利用」的姿态检查** | 只用标准库、不做任何攻击尝试，因此**责任风险为零、信号却很强**：① TLS 证书链与**到期日**（`ssl`）；② **SMB 方言/签名/来宾**（Win11 24H2 起签名默认必需，"未启用"即偏差）；③ 明文协议（Telnet/FTP/TFTP/HTTP 管理面）；④ SNMP `public`/`private` 可用；⑤ **LAN 内存在 LLMNR / NBNS 响应器**（CISA CM0053 已建议关闭 LLMNR，还有响应器就是发现）；⑥ 未加密的 VNC。每一条都要能写进"为什么这么打分" | **P1** |
| **授权范围声明工程化** | 现在是一次性弹窗确认。企业场景需要「本次扫描目标 + 授权依据」随扫描一起落库，并进审计与报表。可加 `--authorization <文本/工单号>` 与策略文件 | P1 |
| **自身供应链安全** | 加 `pip-audit`（CI 里跑）、生成 SBOM、Release 附 **SHA256 + 签名**、提交 VirusTotal 预扫描并在 README 附报告链接 —— 这是**降低杀软误报最有效的动作**，比换打包方式有效 | P1 |
| **离线 CVE + KEV/EPSS 排序** | `[对标]` banner → CPE → CVE 关联，用 **CISA KEV**（已被实际利用）与 **FIRST EPSS**（利用概率）排序。两者都免费、可每日拉取、有 API。**但必须离线可用**：把快照作为可更新数据文件导入，扫描数据一律不出网（内网工具的底线） | P2 |
| **凭据库分层** | 现在是全局一组 SNMP 团体字/SNMPv3 用户 + 一组 WMI 凭据。企业需要「按网段/按设备组的只读账户」。建议做成「凭据配置档（profile）+ 匹配规则」 | P2 |
| **扫描行为审计可视化** | 审计日志已有；补一个「我这台机器过去 24h 向哪些网段发了多少探测包」的自查视图，既是合规，也是自我保护 | P3 |

## 5. 工程与架构建议

### 5.1 数据模型（本建议书里最重要的一条工程改动）

见 §4.3。补充三点工程细节：

1. **迁移必须可回滚**：先「双写」（新表 + 旧 snapshots 表都写），读路径逐步切换，旧库自动升级 + 保留备份文件。这个项目已经有 `ensure_migrated`（JSON→SQLite）的先例，照做即可。
2. **`PRAGMA user_version`**：现在没有任何 schema 版本号。加列时无法判断「这个库是哪个年代的」，只能靠 try/except。加一个版本号 + 顺序迁移列表（`MIGRATIONS = [(1, sql1), (2, sql2), ...]`）。
3. **保留「快照」这一概念不动**：快照是用户能理解的心智模型（「10 月 9 日那份清单」），资产表是**实现**。别把用户可见的概念改掉。

### 5.2 性能与并发

`[实测]` 已发现三处具体问题：

| 位置 | 现象 | 处理 |
|---|---|---|
| `history_store.query_history` | 无 LIMIT、全量取回、Python 聚合；4 万行 605ms；`/16`×20 快照量级会到秒级 | 下推过滤 + 分页 + 资产表 |
| `ui_dialogs/history.py` 两个对话框 | 同步在 GUI 线程执行上面两个查询 | 移入 `QThread`（已有成熟模式） |
| `layout_real_topology` | 10 交换机 → 画布 7326×990；50 交换机 → 36926×990 | 过宽折行/分栏 |

`[实测]` 好消息：布局本身很快（1000 节点 15ms，5000 节点 259ms），**不是计算瓶颈，是排版策略问题**。

其余建议：
- **给扫描引擎加基准测试**：现在只有 3 处零散计时断言。建议建一个 `tests/bench/`（不随常规测试跑），
  固定「/24 全离线」「/24 混合」「单机 1023 端口」三个场景的耗时基线，防止性能悄悄退化。
- **GUI 大表**：`/24` 没问题；`/16`（6.5 万行）时 `QTreeWidget` 会明显吃力。
  建议超过阈值时切换到「分页 + 服务端过滤」或 `QTreeView + QAbstractItemModel`（后者改动大，先测再定）。

### 5.3 质量工程（已很强，补四个缺口）

| 缺口 | 建议做法 | 收益 |
|---|---|---|
| **无覆盖率度量** | 引入 `coverage.py`，**只对领域层设门禁**（`scanner/`、`history_store`、`risk_rules`、`change_detector`、`topology_discovery`），UI 层不设。棘轮式：不低于当前值 | 让「测试很多」变成「测到了哪里」 |
| **无类型检查** | 领域层已是零 Qt 的纯 Python ⇒ 用 `pyright` **只检查领域层**，`basic` 模式起步。UI 层不查（PyQt 存根噪音大） | 拦住「属性名写错」这类只在运行时炸的 bug |
| **无依赖漏洞扫描** | CI 加 `pip-audit`；Release 前跑一次；附 SBOM（`cyclonedx-py` 或 `pip-licenses`） | 供应链合规；企业采购会问 |
| **无 fuzz/属性测试** | 把手写 BER 解析（`scanner/snmp.py`、`scanner/snmp_v3.py`）与指纹正则（`service_fingerprints`）纳入 fuzz。**本次已实测：6 万随机 + 4 万变异输入零异常** —— 固化成测试即可，成本极低 | 把「目前没炸」变成「保证不炸」；`snmp_v3.py`（605 行、解析不可信输入）是最高风险点 |

另外两条小的：
- **`topology_discovery.py` 已 1283 行**，其中 SNMP I/O、LLDP/CDP 解析、FDB、布局、文案混在一起。
  建议**只做一次轻拆分**：抽出 `layout.py`（纯函数，已被证明可单测）与 `models.py`（TopoNode/Link/Topology），
  其余保持 —— 不必照 `ui_dialogs/` 那样拆成 8 个文件。
- **`main_window.py` 1676 行**是现在最大的文件（`ui_dialogs` 拆分已证明这条路可行，`main_window.py`
  可同样按 Mixin 拆：工具栏/菜单、状态栏、结果控件、快捷键）。

### 5.5 许可证与 Qt 版本（战略级，建议尽早决策）

**现状**：PyQt5 ⇒ 整体必须 GPL-3.0（或买 Riverbank 商业授权）。README 的论证是正确的。

**建议：迁移到 PySide6（Qt 6）。** 四个独立理由：

1. **许可证自由度**：PySide6 是 **LGPL-3.0**（Qt 官方绑定）。动态链接 + 提供替换能力 + 声明
   即可用于闭源分发。意义是：你可以做「开源核心 + 闭源增值模块」，也可以被企业集成，
   而不必买商业授权。这一条**直接决定项目能不能有商业模式**。
2. **运行时安全**：Windows 上的 `PyQt5-Qt5` 只有 **5.15.2（2021-07）**，而 Qt 5.15 的后续补丁
   **只对商业客户开放**；开源社区的补丁来自 KDE 的 Qt5 Patch Collection（已跟进到 5.15.19），
   但那是**发行版源码级**的，Windows wheel 拿不到。对一个「解析不可信网络输入、跑在 Windows 上」
   的工具，这意味着长期贴着 5 年未获上游安全修复的 Qt 运行时。
3. **可持续性**：PyQt5 已不再跟随 Qt 6 演进；新系统/新 Python 版本的适配会越来越靠运气。
4. **Windows ARM64**：`[对标]` PySide6 有官方 `win_arm64` wheel，**PyQt5 没有**（只有社区构建）。
   想让本工具跑在骁龙 PC 上，唯一的路就是这次迁移。

**成本与做法**（务实评估：这是一个「几天」级而非「几周」级的迁移）：

- 依赖替换：`PyQt5` → `PySide6`；`requirements.txt` / `pyproject.toml` / 两个 `.spec` 的
  hiddenimports 同步；
- 已知的机械差异：`app.exec_()` → `app.exec()`；枚举需全限定（`Qt.AlignCenter` →
  `Qt.AlignmentFlag.AlignCenter`，**这是最费时的一项**，但可以用脚本批量处理）；
  `QAction` 从 `QtWidgets` 移到 `QtGui`；`QRegExp` → `QRegularExpression`；
  `pyqtSignal` → `Signal`、`pyqtSlot` → `Slot`；`QDesktopWidget` 已移除；
  `.connect` 的 `type=` 参数写法不同；
- 本项目**几乎没有用 Qt Designer 的 `.ui`**（界面全是代码构建），这**大幅降低**迁移成本；
- 建议路径：**新开一个 `qt6` 分支**，先跑通「启动 + 扫描 + 列表 + 导出」四条主链路，
  再逐个对话框迁移；测试套件（1116 个用例、大量走 `QT_QPA_PLATFORM=offscreen`）是这次迁移的
  安全网 —— 这正是过去两年把测试写厚的回报。
- **如果短期不做**：至少在 README 的「已知限制」里**如实写出**「Windows 版捆绑的 Qt 运行时为
  5.15.2（2021），上游开源分支已停止安全更新」，让用户自己判断。诚实是这个项目一贯的风格，
  这里也应该一致。

## 9. 明确不建议做的（陷阱清单）

| 陷阱 | 为什么不做 |
|---|---|
| **云端 MSP 多租户平台 / 强制账号** | `[对标]` 这是该品类**第 7 大抱怨**（Fing 要账号）。本项目的定位优势恰恰是「本地、无账号」。做云等于放弃最强差异点，还要背合规与运维 |
| **SNMP 轮询式持续监控**（Zabbix/PRTG 的地盘） | 需要常驻服务、时序库、告警风暴治理 —— 是另一个产品。**只做「按需 + 定时扫描」**，把结果交给 Prometheus/Zabbix |
| **自建时序指标库**（RRDtool/TSDB） | `[对标]` 降采样、保留策略、基数治理是另一个产品。保留快照 + diff，把指标**推给**真正的 TSDB |
| **DCIM 式「强制外键链」真值模型** | `[对标]` NetBox 最被抱怨的上手难点就是「建任何设备前必须先建好整条外键链」。本项目应允许**自由格式台账**，把层级结构留给 NetBox |
| **配置备份与合规基线**（Oxidized/NetCrunch 的地盘） | `[对标]` Oxidized 为此维护 130+ 设备型号与一套提示符/分页 DSL —— 那是个无底洞，而且需要你未必拿得到的写权限凭据。**只导出 `router.db` 让别人去做** |
| **分布式轮询 / 多服务器扩展 / 每台终端装 agent** | `[对标]` LibreNMS dispatcher、Zabbix proxy 之所以存在是因为它真的难；而"不装 agent 就能看见一切"正是 Windows 工具的魅力。多站点应该是**文件/API 交换**，不是装 agent |
| **爆破 / 漏洞利用 / DoS 类检查** | `[对标]` Nmap 明确警告脚本无沙箱、Nuclei 警告不要以服务方式运行。风险评分只能是**暴露面启发式**（Telnet 开着、SNMP 用 `public`、默认凭据横幅），**绝不能**给出暗示"已实测可利用"的 CVE 结论 —— 那是责任而不是功能 |
| **把「协议/厂商覆盖面」当成目标** | `[对标]` LibreNMS/Observium 用海量 OS profile 换广度，靠的是团队规模。应把**一条指纹路径做到极致**（OUI + SNMP sysDescr/sysObjectID + mDNS + NetBIOS），长尾交给 NetBox/Oxidized |
| **完整插件/代码执行机制**（归档评审的 P2-3） | 一个「允许第三方代码在扫描器里跑」的设计会带来 API 稳定性 + 安全 + 沙箱三重负担，对单人维护者性价比极低。`[对标]` Nmap 自己都说第三方脚本可能损害你的系统。**建议改成「声明式扩展」**：像 `service_fingerprints.json` / `oui.db` 那样，把新增指纹/端口/厂商做成**数据文件**（可选插件目录，只读 JSON/YAML，不执行代码）。这既拿到了 80% 的收益，又不用背 API 兼容包袱 |
| **`oui.db` 迁 Git LFS**（归档评审的 P2-5） | 1.95 MB 二进制、低频变更，Git 完全可承受。LFS 会让 clone 依赖 LFS 客户端并消耗带宽配额，**净收益为负**。建议正式关闭该条目 |
| **为了「体积小」改回 onefile** | README 里「onefile 自解压即执行 → 触发 EDR 启发式」的论证成立。体积不是本项目的痛点，**误报才是**。`[对标]` 业内共识同样是不要 onefile + UPX |
| **捆绑 Npcap（或任何抓包驱动）** | `[对标]` Npcap 免费授权限 **5 次安装**且**明确禁止再分发**，捆绑需要付费的 OEM 再分发授权。而且这类驱动安装本身就会触发 EDR 告警。正确姿态是**检测 + 优雅降级**（现在就做对了） |
| **把 MAC 当作唯一资产身份** | `[对标]` 现代手机/Windows 会随机化 MAC，IPv6 还有隐私地址 —— 纯 MAC 身份会让这些设备"每次扫描都是新设备"，制造大量假变更告警。**MAC 为主 + 随机化标志 + 主机名/指纹兜底**才是能用的设计（见 §4.2） |
| **做完整的 IPv6 资产盘点** | 一个 /64 有 2^64 个地址，IPv6 的"扫描"在语义上就不成立。**只做可见性**（NDP 缓存 + `ff02::1` 多播 + mDNS over v6），把它挂在已有 IPv4 资产上 |
| **追 gNMI / NETCONF / YANG / 流式遥测** | `[对标]` IETF 126 的会议材料直言 YANG Push/RFC 8641 的**市场采用"相当缓慢"**。对一个桌面工具，投入产出比极低；SNMP 才是该继续加固的那条路（v3 优先，这正是本项目的现状） |
| **做 Wi-Fi 监控模式（monitor mode）站点勘测** | `[对标]` 在 Windows 上是死路（驱动/NDIS 限制），别投入。只做 Native Wi-Fi API 能拿到的那一片（信道拥塞、漫游日志、SSID↔子网） |
| **对 OT 设备做任何写操作** | `[对标]` 工控网络里一次"无害"的写操作可能停掉产线。**只读识别**（BACnet `Who-Is` / Modbus 读设备标识 / Matter mDNS 发现）是唯一可接受的边界 |
| **买 EV 证书** | 2024 起 EV 不再免 SmartScreen，纯溢价 |
| **自研 LLM/聊天助手** | 内网工具的数据不能出网；做「只读 MCP + 自然语言查询接口」比内置模型务实得多 |
| **为 MSIX/Store 上架改架构** | `schtasks`、原始套接字、任意路径写入与 MSIX 模型冲突大，改造成本远高于收益 |
| **一次性全量重写 UI/数据层** | 1116 个测试是资产，渐进式改造（双写、门面、Mixin 拆分）已经被 `ui_dialogs/` 那次证明可行 |
